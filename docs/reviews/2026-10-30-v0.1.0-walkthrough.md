# v0.1.0 browser walkthrough (2026-10-30)

Release checklist step 3 asks for every page to render on the demo data with numbers matching
`sample_data/demo/expected/` ([release.md](../release.md#checklist)). This is that walkthrough
on the local Quick start path, in a real browser, before the v0.1.0 tag. It does not replace
the self-hosted stack walkthrough (TLS proxy, `pg_dump`/restore), which is still open.

## Setup

- Fresh clone of `main` at `328e50c`, then the README Quick start exactly as written: `uv sync`,
  `cp .env.example .env`, `export DATABASE_URL=sqlite:///db.sqlite3`, `migrate`,
  `load_sample_data` (43 rows, 32 accepted, 10 refused, 1 exact duplicate ignored, 8
  warnings), `createsuperuser`, `runserver`. Also `create_workspace demo` for the event pages.
- The Postgres variant from the README's `<details>` block was also run: `docker compose up -d
  --wait db` (PostgreSQL 17 healthy), `migrate` and `load_sample_data` with the `.env.example`
  `DATABASE_URL`.
- Browser: Chromium 1234 (Playwright for Python 1.62.0), 1280 x 900, plus 390 x 844 for the
  phone checks. Every page was driven by a script: clicks, radio changes (HTMX swaps), file
  uploads, the SDK demo buttons, Back, sign-out. Console messages, page errors, failed requests
  and HTTP 4xx/5xx were recorded per step.

**Numbers against `sample_data/demo/expected/models.json`:** every campaign row in every
currency block was read from the page and compared. Pipeline: EUR, JPY and USD match exactly.
Won: USD matches; EUR matches except that the page prints a zero credit as `0` where the
fixture writes `0.00` (the template shows every zero as a muted `0`; the value is the same).

**Console:** no JavaScript errors, no page errors, no failed requests on any page. The only
console errors are Chromium's own "Failed to load resource" lines for the three intentional
4xx responses above (empty import form, unknown metric, unknown opportunity).
